# Android Bridge — File Map

## Gradle and manifest

| Path | Purpose |
|---|---|
| `android/build.gradle` | Module gradle. Pins `clevertap-android-sdk 8.1.0`. `compileSdk 36`, `minSdk 23`, `targetSdk 36`. Selects oldarch/newarch source sets based on `newArchEnabled`. Publishes as `com.clevertap.react:clevertap-react-native`. |
| `android/src/main/AndroidManifest.xml` | Scaffolding only — host app supplies its own activities, services, and permissions. |
| `android/build/` | Generated output. Ignore — local artifact. |

## Shared (`android/src/main/java/com/clevertap/react/`)

| File | Lines | Role |
|---|---|---|
| `CleverTapModuleImpl.java` | ~1500 | The bridge implementation as a plain helper class — does NOT extend `ReactContextBaseJavaModule` and has NO `@ReactMethod` annotations. Holds the active `CleverTapAPI` instance. Exposes ~126 plain public methods grouped by feature (push, profile, inbox, in-app, variables, custom templates, display units, …). Called only from the two arch shims. |
| `CleverTapPackage.kt` | small | `ReactPackage` returning the single `CleverTapModule` for the active architecture. Host apps add `new CleverTapPackage()` to `MainApplication.getPackages()`. |
| `CleverTapApplication.kt` | small | Convenience base `Application` class hosts can extend; auto-registers the SDK with `CleverTapAPI.setNotificationHandler` if push template SDK is present. |
| `CleverTapEvent.kt` | small | Enum of every event name. Each entry: `eventName: String`, `isBufferable: Boolean`. Single source of truth for event naming. |
| `CleverTapEventEmitter.kt` | small | Wraps `DeviceEventManagerModule.RCTDeviceEventEmitter`. Buffers bufferable events when `hasListeners == false`. Exposes `onEventListenerAdded()` to flip the flag and flush. |
| `CleverTapListenerProxy.kt` | medium | Single proxy instance registered on `CleverTapAPI`. Implements every CleverTap-SDK listener interface (push permission, in-app, inbox, variables, display units, custom templates, feature flags, product config). Translates each callback to a `CleverTapEvent` + `WritableMap`. |
| `CleverTapUtils.java` | medium | Static helpers: `getWritableMapFromMap`, `getWritableArrayFromList`, `toMap`, `toArray`, `getJsonFromMap`, `getMapFromJson`. Handles nested structures correctly. |
| `CleverTapRnAPI.kt` | small | Public Kotlin API host apps call from their Application class to initialize the SDK (account ID + token + URI). |
| `Constants.kt` | very small | `REACT_MODULE_NAME = "CleverTapReact"`. `FCM` push type string. |

## Old-arch shim (`android/src/oldarch/CleverTapModule.kt`)

| File | Role |
|---|---|
| `CleverTapModule.kt` | Extends `ReactContextBaseJavaModule`. Constructor takes `ReactApplicationContext` and creates a `CleverTapModuleImpl`. Every bridge method is annotated with `@ReactMethod` and forwards to `cleverTapModuleImpl.<method>(...)`. `getName()` returns `Constants.REACT_MODULE_NAME` (`"CleverTapReact"`). |

## New-arch shim (`android/src/newarch/CleverTapModule.kt`)

| File | Role |
|---|---|
| `CleverTapModule.kt` | Extends `NativeCleverTapModuleSpec` (codegen output from `src/NativeCleverTapModule.ts`). Same forwarding pattern as the oldarch shim, but methods are `override fun ...` instead of `@ReactMethod fun ...`. The TurboModule registration is autogenerated by RN codegen. |

## Anti-pattern note

The two shims look almost identical and it's tempting to abstract them. Don't. Each shim's base class is different (`ReactContextBaseJavaModule` vs `NativeCleverTapModuleSpec`) and the TurboModule contract evolves with React Native — keeping them as straight forwarders makes upgrades trivial.
